# Спецификация протокола

Транспорт - **UDP**, порт по умолчанию **8080**. Один пакет = одна датаграмма.
Максимальный размер пакета - **512 байт** (заголовок 9 байт + до 503 байт данных).

## 1. Общие правила

- Все многобайтовые целые передаются в **big-endian** (сетевой порядок байт).
- `float` - IEEE-754 binary32; передаётся его 32-битное представление, также в big-endian.
- Выравнивания нет: поля идут подряд без пропусков. Сериализация выполняется **поле за полем**
  (`ByteWriter`/`ByteReader` в `src/common/protocol.h`), поэтому результат не зависит от
  компилятора, `#pragma pack` и порядка байт процессора.
- Строки - «короткие»: 1 байт длины + байты строки (UTF-8), без завершающего нуля.

## 2. Заголовок (9 байт)

| Смещение | Размер | Поле          | Тип      | Описание |
|---------:|-------:|---------------|----------|----------|
| 0        | 1      | `type`        | uint8    | тип пакета (`PacketType`, см. п. 3) |
| 1        | 2      | `seqNum`      | uint16   | порядковый номер. Клиент увеличивает его на 1 с каждым пакетом (после 65535 идёт 0). Сервер в ответе повторяет `seqNum` запроса |
| 3        | 2      | `payloadSize` | uint16   | размер данных после заголовка, байт |
| 5        | 4      | `checksum`    | uint32   | CRC-32 (IEEE 802.3, полином `0xEDB88320`) всего пакета (заголовок + данные), при расчёте поле `checksum` считается равным 0 |
| 9        | N      | `payload`     | -        | данные, `N = payloadSize` |

## 3. Типы пакетов

| Код    | Имя        | Направление | Payload           | Ответ сервера |
|--------|------------|-------------|-------------------|---------------|
| `0x01` | `MOVEMENT` | C → S       | `MovementPayload` | `STATE` или `ACK` с ошибкой |
| `0x02` | `SHOOT`    | C → S       | `ShootPayload`    | `ACK` |
| `0x03` | `ACK`      | S → C       | `AckPayload`      | - |
| `0x04` | `LOGIN`    | C → S       | `LoginPayload`    | `ACK` |
| `0x05` | `STATE`    | S → C       | `MovementPayload` | - |

### 3.1 MovementPayload (12 байт) - `MOVEMENT`, `STATE`

| Смещение | Размер | Поле | Тип     | Описание |
|---------:|-------:|------|---------|----------|
| 0        | 4      | `x`  | float32 | координата X |
| 4        | 4      | `y`  | float32 | координата Y |
| 8        | 4      | `z`  | float32 | координата Z |

В `MOVEMENT` - **желаемая** позиция клиента. В `STATE` - **авторитетная** позиция после
обработки на сервере: перемещение за одну команду ограничено 10 единицами, координаты -
диапазоном `[-100; 100]`.

### 3.2 ShootPayload (1 байт) - `SHOOT`

| Смещение | Размер | Поле       | Тип   | Описание |
|---------:|-------:|------------|-------|----------|
| 0        | 1      | `weaponId` | uint8 | идентификатор оружия, допустимо `1..5` |

### 3.3 LoginPayload (2 + L + P байт) - `LOGIN`

| Смещение | Размер | Поле          | Тип   | Описание |
|---------:|-------:|---------------|-------|----------|
| 0        | 1      | `loginLen`    | uint8 | длина логина `L`, 1..32 |
| 1        | L      | `login`       | bytes | логин |
| 1+L      | 1      | `passwordLen` | uint8 | длина пароля `P`, 0..32 |
| 2+L      | P      | `password`    | bytes | пароль |

> Пароль передаётся открытым текстом - допустимо только в учебных целях.
> В реальном проекте нужен DTLS или challenge-response с хешем.

### 3.4 AckPayload (2 байта) - `ACK`

| Смещение | Размер | Поле        | Тип   | Описание |
|---------:|-------:|-------------|-------|----------|
| 0        | 1      | `ackedType` | uint8 | тип подтверждаемой команды |
| 1        | 1      | `status`    | uint8 | результат (`Status`, см. п. 4) |

## 4. Коды статуса

| Код    | Имя               | Когда возвращается |
|--------|-------------------|--------------------|
| `0x00` | `OK`              | команда принята |
| `0x01` | `NOT_AUTHORIZED`  | `MOVEMENT`/`SHOOT` до успешного `LOGIN` |
| `0x02` | `BAD_CREDENTIALS` | неверный логин или пароль |
| `0x03` | `BAD_PAYLOAD`     | размер или содержимое payload не соответствует типу |
| `0x04` | `UNKNOWN_WEAPON`  | `weaponId` вне диапазона `1..5` |
| `0x05` | `UNKNOWN_TYPE`    | неизвестный `type` |

## 5. Обработка на сервере

1. Датаграмма короче 9 байт → отбрасывается.
2. `9 + payloadSize` ≠ размер датаграммы → отбрасывается.
3. CRC32 не совпадает → отбрасывается **без ответа** (заголовку нельзя доверять).
4. Для всех типов, кроме `LOGIN`: если `seqNum` не новее последнего принятого от этого клиента
   (сравнение с учётом переполнения: `(uint16)(a - b) < 0x8000`) → дубликат/устаревший, игнорируется.
5. Проверяется payload и авторизация, команда применяется, отправляется ответ.
6. Каждая полученная команда и каждый отброшенный пакет записываются в лог
   (консоль + `server.log`).

Клиент идентифицируется парой `IP:port`. Учётные записи (заданы на сервере):
`player1/qwerty`, `player2/12345`, `admin/admin`.

## 6. Пример: MOVEMENT (1.0, -2.5, 0.0), seq = 6

```
01             type = MOVEMENT
00 06          seqNum = 6
00 0C          payloadSize = 12
XX XX XX XX    checksum (CRC32)
3F 80 00 00    x =  1.0
C0 20 00 00    y = -2.5
00 00 00 00    z =  0.0
```

Итого 21 байт. Корректность раскладки проверяется тестом `tests/test_protocol.cpp`.
